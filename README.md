# Porto Seguro’s Safe Driver Prediction

## О проекте
Решение соревнования с Kaggle по предсказанию вероятности подачи страхового иска водителем в следующем году. В проекте реализован полный пайплайн: от разведочного анализа и генерации признаков до взвешенного блендинга трех SOTA-алгоритмов градиентного бустинга.

**Датасет:** https://www.kaggle.com/c/porto-seguro-safe-driver-prediction

**Оптимизируемая метрика:** Normalized Gini Coefficient.

## 1. EDA и Feature Engineering (Что сработало)

* **Обработка пропусков:** Все значения `-1` (так в датасете обозначались пропуски) были переведены в `NaN`, чтобы градиентные бустинги могли обрабатывать их встроенными алгоритмами.
* **Генерация `missing_count`:** Добавлен новый признак — количество пропущенных значений в строке. В страховании отказ клиента заполнять часть анкеты является сильным поведенческим фактором риска. Метрика показала рост.
* **Удаление шумовых признаков:** Матрица корреляций показала, что весь блок признаков `ps_calc_` имеет нулевую связь с целевой переменной. Удаление этого математического мусора уберегло модели от переобучения.

## 2. Что НЕ сработало (Проверка гипотез)

В процессе работы тестировались разные подходы к созданию признаков. Анализ тепловой карты (Heatmap) показал сильную мультиколлинеарность некоторых фичей (например, `ps_reg_02` и `ps_reg_03` коррелировали на 0.74).
* **Гипотеза:** Создать полиномиальные признаки через перемножение сильно коррелирующих столбцов.
* **Результат:** CV Gini обвалился с 0.27777 до 0.26119.
* **Вывод:** Градиентные бустинги сами отлично находят нелинейные связи. Явное ручное перемножение создало жесткий и слишком специфичный сигнал. Модели просто вызубрили тренировочные фолды (переобучились) и провалились на валидации. **От этой идеи осознанно отказались.**

## 3. Архитектура и Валидация

Для оценки моделей использовалась строгая кросс-валидация **StratifiedKFold на 5 фолдов**. Это критически важно из-за сильного дисбаланса классов (аварий всего около 3.6% в датасете).

**Базовые модели:**
Для обеспечения разнообразия (diversity) были выбраны три алгоритма с разной логикой построения деревьев:
1. **LightGBM** (leaf-wise рост)
2. **XGBoost** (level-wise рост)
3. **CatBoost** (симметричные деревья)

## 4. Ансамблирование (Weighted Blending)

Вместо классического тяжелого стекинга, который мог легко переобучиться на наших предсказаниях, был использован **взвешенный блендинг (Weighted Blending)**. 

Веса для OOF-предсказаний (Out-of-Fold) каждой модели не брались из головы, а были математически подобраны через оптимизатор `scipy.optimize.minimize` (метод SLSQP), чтобы найти идеальные доли, дающие абсолютный максимум ROC-AUC на кросс-валидации.
